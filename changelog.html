v0.2.3 prepared 21 Oct 2026 In development

Not submitted yet. Will ship once v0.2.2 review completes.

Changed

  • Checksum verification on restore. Before opening any tab, TabGuard now recomputes the SHA-256 checksum of the stored session and compares it with the checksum saved at save time. If they differ, restore is blocked with a clear message instead of opening a corrupted session.
  • Clearer error on restore. When verification fails, the popup says "Data corrupted: checksum mismatch" instead of a generic "Restore failed".

Fixed

  • Unused permission removed. The storage permission was declared in v0.2.2 but never used — all session data lives in IndexedDB. It has been removed from the manifest.
  • Auto-backup growth. Auto-backups are now capped at 20. Older auto-backups are deleted as new ones are created, so IndexedDB no longer grows without bound for long-running installs.
Why this matters: v0.2.2 listed "verified saves" as a feature, but the verification step only compared tab counts. v0.2.3 makes the claim literal — the checksum is actually re-verified on every restore.
v0.2.2 21 Oct 2026 In review

Changed

  • Free for everyone. The Pro tier, trial logic and payment integration from earlier builds were removed. All features are unlocked, with no account and no license key.
  • Zero network requests. The extension makes no calls to any server. All data stays in your browser.
  • Reduced permissions. host_permissions is empty. Only tabs, storage, unlimitedStorage and alarms are requested.

Added

  • Restore preview with tab count, window count and estimated RAM.
  • One-click JSON export per session.
  • Auto-backup every 30 minutes while Chrome is open.

Fixed

  • Eleven Chrome Web Store submission errors resolved before the first submission.
